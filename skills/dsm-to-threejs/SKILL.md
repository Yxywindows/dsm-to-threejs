# 场景建模、Web 展示与成片

按用户要的交付选入口。建模从图像、几何和测量证据开始。已有模型要拍宣传片、漫游或结构演示时，直接读[三维场景成片](references/scene-film.md)。要交互网页时读 [Web 交付说明](references/web-delivery.md)。只要求模型时，交付到模型为止。

## 开始前

1. 先读当前项目 `AGENTS.md` 和现有任务记录，定位项目根目录、实际输入、已交付模型和可复用产物。不得因路径存在或旧检查通过就认定内容相同或可复用；无历史检查记录时，不要求用户补交旧 pass，先做本次适用的只读检查并建立基线。
2. 已有模型只需出片或接入 Web 时，先检查该资产，再进入相应交付流程。若还要求建模或修正资产，先完成指定范围的修改。收到当前场景的修正或完善反馈时，识别最近一版可打开、可核对的交付及受影响对象，按[局部迭代](references/routes.md#局部迭代)继续。新任务先依据目标和证据选路线：扫描保真切分（scan）、参数化重建和适用生成资产（hybrid）、增量展示材质（showcase）或使用 MCP 简化建模。只有路线选择会实质改变用户要的结果且上下文不足时，才用一组简短问题澄清。
3. 先检查已提供材料和项目现场，再说明有用的替代来源。只询问继续工作所必需的缺项，合并对象范围、用途、输入和确实必要的尺寸等问题。照片、点云或文字可直接作为证据。未知尺度或可选尺寸保留未知；有空间依据且用户目标允许时，可做明确标注的估算。
4. 实际打开图像或检查几何后再把它记为已查看；记录来源、对象稳定 ID、参数、单位和不确定性。只拿到路径或文字摘要不算已读证据。
5. 任何新增或修改几何、布局、颜色或材质之前，按项目指定模板创建本任务五节建模任务书并分享路径；没有指定模板时使用[随包模板](assets/modeling-brief.md)。任务书是生产记录，不是额外批准门槛。仅剪辑、架设摄影机或接入 Web 时，可复用原任务记录。
6. 使用 Blender 前先读可用的 `blender-core` skill；新建或修改场景几何、材质及布局后，运行适用的 `blender-asset-qa` skill，并实际打开查看验收图。若相关 skill 不可用，执行等价的拓扑、法线、退化/重复面、悬浮/穿插、UV 和材质检查及实际图像复核，并列明未覆盖项；不得以“看起来无破面”声称完整 QA。碰撞只在目标物理/交互需要时制作；纯静态展示可标为不适用。
7. 每个阶段用简短中文报告当前步骤、已实际生成/检查的产物、下一步。普通已授权阶段自动接续；只在会实质改变交付、缺少必需证据或工具权限阻断时等待用户答复，不在每阶段另加确认。

## 执行原则

### 自主建模时如何发现细节

整场新建、重建或整体优化时，即使用户只说“按原图建模”，也要主动执行下面的读图、试建和复核。明确指定局部修改时，只在该范围、相邻接口和共享资源上使用这套方法。已有可信盘点时从它继续，对照当前证据补漏。

1. **从原图找对象。** 先看全景划分区域，再放大各区，沿边缘、交界和遮挡处扫一遍。从源资料中辨认地物，再与已有清单或模型双向核对，找出漏项、无依据的新增、错放和误合并。留意平面上的标线与铺装变化、细杆件、附属设施和重复组里的例外。名称一时不明而轮廓清楚时，用位置与外形暂记。只有文字或未着色点云时，按其实际提供的形状、位置或描述建账。
2. **决定每项怎样呈现。** 在已有五节任务书的“对象与场景”或所引用的清单里，为每个可辨实例或重复组留下源图位置、关键可见特征和表达方式。可以独立建模、作为构件、做成表面图案或按目标视距简化。同组记录可辨的数量、分布及例外；共用资产前核对实例之间的形状、朝向、附属件和材质差异。小物件若决定出入口、连接或识别特征，也要保留。遮挡和分辨率不足处注明可见边界。
3. **在批量复制或精细贴图前看一版。** 有参考图时按对应视角对照初稿；只有点云时看投影或剖面，只有文字时核对描述的形状、数量和关系。查看初稿时，先看大形、位置、支撑和连接，再看能区分实例的轮廓、开口、图案或材质。重复物先看代表件及例外件，发现共性问题就修生成规则。没有专门指南的地物同样处理：把观察写成可验证的问题，例如“这一排设施是否都朝同一边”“踏板有没有接到平台”，选择能作判断的最简检查。证据清楚的范围内直接修正并复看。
4. **交付前从原始证据再看一遍。** 将各区域的原始证据与最终导出件对照，逐项核对可辨地物的去向，以及早期发现的差异是否在成品中消失。对影响目标视角、空间关系或功能的未解项补看局部，修正后复核受影响部分。原图无法分辨或超出明确范围的细节，交付时说明其限制。沿用现有任务书、机位和检查点即可，无需另开一份全场报告。

### 测量与交付

- 按 [路线说明](references/routes.md) 完成建模和交付。专项测量可由模型主动发现的差异触发。按当前证据、用途及修改影响选测；结果足以作决定就停止扩展，复用输入、方法与输出均可核实的已有结论。
- 按 [Web 交付说明](references/web-delivery.md) 完成独立 GLB/纹理回读、Web 副本优化、three.js 接入及浏览器测量。只在用户明确要求三维到 Web 时默认进入此路线，并告知工作范围；模型任务本身不强制 Web。
- 持久化任务状态默认放在 `<project-root>/artifacts/<task-id>/task-state.json`；已有项目流水线约定优先。至少记录 `task_id`、`route`、`goal`、`current_stage`、`pending_questions`、`stages`、`artifacts`、`checks`、`next_action`。各阶段的输入、参数、代码、运行时、上游和输出指纹，以及起止时间、日志和状态，可直接引用项目已有的检查点或阶段日志。暂停恢复先读状态和未答问题，沿用已回答信息，不重做初次问询。只复用所有依赖指纹匹配且当前输出哈希一致的成功阶段；同路径或旧“通过”不够。失败/未运行明确标出，不伪造耗时、token、显存、FPS或验收结论。
- 当前真实材料或工具阻塞时，列出缺项、已完成部分和可继续的选择后等待；不虚报完成。外部发布或部署需要用户明确授权。
- 先读项目 `AGENTS.md` 并遵循其 lead/review、委派与验收约定。根据设备内存安排重型渲染与推理的并发量。

- 场景中车辆的外形、停放方向、接地或贴图需要还原时，按 [逐车对照与修正](references/vehicles.md) 选择能检验当前差异的方法。
- 用户要求 three.js/Web 交付时读 [Web 交付说明](references/web-delivery.md)。
- 项目有自己的流水线时，读[项目适配](references/project-adapter.md)和项目内的适配记录。
